# Agent offer follow-up, backup-offer acceptance and submission

Apply AGENTS.md and the packaged entry contract. This is a resale buyer's-agent
question, not a seller asking about Opendoor's acquisition offer.
Required full-playbook sections when not loaded: [Access codes](../SKILL.md#access-codes)
and [Submission surfaces](../SKILL.md#submission-surfaces), together by exact heading.
AGENTS.md's current agent submission URL takes priority over older URL wording.

1. Verify ticket/requester/channel/newest intent. Add comments only for a missing
   conversation fact. For a named home, resolve that exact property and verify its
   listing stage. Batch independent initial lookups, never guess returned tokens.
2. Preserve AGENTS.md's recent-notes/activity check for a record-specific concern;
   use [resolution-first access](access-resolution.md) if the ask includes access.
   If a later call already resolved the same concern, stop with the required
   no-reply disposition and internal note naming the verified handler.
   Later general submission instructions or document checklists do not establish
   receipt, review, availability or resolution of an offer already emailed for a
   named home. Match the actual question and property before taking no-reply.
   For a submitted-offer follow-up, verify the exact property's current listing
   status even when generic instructions were sent later. If sold, say it has
   sold and is no longer available for offers; do not repeat submission guidance
   or recommend closing without a reply on the strength of that generic SMS.
3. Opendoor accepts backup offers. When directing an agent to submit, include
   `https://www.opendoor.com/make-offer`: enter the property address and follow the
   prompts to submit the offer. Do not name the portal without its URL or promise
   acceptance, a response, or an appointment. Keep buyer and seller submission
   paths distinct; use their existing recipe if the requester is not an agent.
4. If the home is under contract, it cannot be viewed, including for a backup
   offer. Do not route a viewing to an app, support, or showing service. Acceptance
   of backup offers and a system permitting booking do not override this gate.

Stop when the requested acceptance/submission answer, listing stage and required
resolution checks are supported. Skip trust, credentials, Flags or access research
solely to enrich a submission-only answer; a separate access ask keeps those gates.
No offer amounts, former-seller history or invented availability. Customer reply
first and internal note second, in separate non-empty copy boxes.
