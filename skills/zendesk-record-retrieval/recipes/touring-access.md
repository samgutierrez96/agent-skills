# Touring/access

Apply the packaged entry contract and project rules before this recipe.
The full playbook remains authoritative: [Access codes](../SKILL.md#access-codes); [Trust level](../SKILL.md#trust-level).
For assessment/photo/app/walkthrough, stage-sensitive, ambiguous, or multi-record asks,
read the matching full-playbook section before drafting; this card is the first lookup path.

- First follow [resolution-first access](access-resolution.md). Stop if recent
  notes confirm this request was already resolved. Otherwise continue below.
- **Unresolved touring/access:** Zendesk MCP → property listing stage and any
  existing appointment's booking/confirmation timing. Honor a viewing already
  scheduled or confirmed before the home went under contract; do not honor one
  booked afterward. Unknown timing requires verification before a scheduling
  decision, not automatic cancellation. Otherwise under contract means no new
  viewing, including an agent preview for a backup offer. Do not send the requester
  to phone support, an app, or a showing service to schedule a prohibited viewing.
  Older tours-until-closing guidance and a system allowing booking do not override
  this gate. Keep required identity/access safeguards for a qualifying appointment.
- When the listing stage permits viewing: customer lookup → property Flags and
  actual Home Access self-tourability. Self-tourable homes permit any eligible
  requester after required identity verification; non-self-tourable homes requiring
  agent access need verified agent information. A denied self-identified agent
  with outstanding verification follows the agent-verification card to collect
  missing credentials, not a phone-support-only referral. Never provide a code,
  remote unlock, or direct entry while denial/verification is unresolved; preserve
  non-negotiable Trust and Safety and rental-scam restrictions.
