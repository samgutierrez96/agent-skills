# Touring/access

Apply the packaged entry contract and project rules before this recipe.
The full playbook remains authoritative: [Access codes](../SKILL.md#access-codes); [Trust level](../SKILL.md#trust-level).
For assessment/photo/app/walkthrough, stage-sensitive, ambiguous, or multi-record asks,
read the matching full-playbook section before drafting; this card is the first lookup path.

- First follow [resolution-first access](access-resolution.md). Stop if recent
  notes confirm this request was already resolved. Otherwise continue below.
- **Access-issue Home Feedback ticket input (November 24):** Use the home-issue
  macro with `Severity`, `Issue`, `Area`, `Notes`, and `Able To Access`.
  `Able To Access` must be exactly `Yes` or `No`, based on confirmed facts;
  an unsuccessful code/door attempt alone does not prove no other access.
  Clarify an unknown value rather than defaulting it. This is the report body,
  not a replacement for Zendesk's reply/internal-note boxes or the XA call note.
  Do not infer severity from one example, reclassify completed reports, create
  another ticket, submit, dispatch a vendor or promise resolution. Sources:
  https://opendoor.slack.com/archives/C02K6JVSNUF/p1795550961051789 and
  https://opendoor.slack.com/archives/C02K6JVSNUF/p1795554332314589.
- **Failed tour from an access issue (November 18 XA update and owner replies):**
  thank the caller, apologize and take ownership; do not give a resolution date
  or promise a callback/outbound follow-up. Do not invite another trip before
  access is confirmed. Retain what happened, what was tried/told and a verified
  triage-ticket link if one exists in the internal note. Give only the latest
  confirmed status on an inbound follow-up; do not treat proposed thread ideas
  as required process. Source:
  https://opendoor.enterprise.slack.com/archives/C02K6JVSNUF/p1795046789458139.
- **Existing current-hour access CBR (November 23):** Notes must identify an
  agent/appraiser access callback request, an unanswered first attempt, and an
  appointment and communications matching the current hour. The XA makes one
  immediate second courtesy attempt before the next call; hours-old requests
  do not need it. This is not a later repair-status callback promise and does
  not authorize assistant calls or bypass identity/Trust/access gates. Document
  actual attempts only. Source:
  https://opendoor.slack.com/archives/C02K6JVSNUF/p1795462285205729.
- **Unresolved touring/access:** Zendesk MCP → property listing stage and any
  existing appointment's booking/confirmation timing. Honor a viewing already
  scheduled or confirmed before the home went under contract; do not honor one
  booked afterward. Unknown timing requires verification before a scheduling
  decision, not automatic cancellation. Otherwise under contract means no new
  viewing, including an agent preview for a backup offer. Do not send the requester
  to phone support, an app, or a showing service to schedule a prohibited viewing.
  Older tours-until-closing guidance and a system allowing booking do not override
  this gate. Keep required identity/access safeguards for a qualifying appointment.
- When the listing stage permits viewing: customer lookup → property Flags and
  actual Home Access self-tourability. Self-tourable homes permit any eligible
  requester after required identity verification; non-self-tourable homes requiring
  agent access need verified agent information. A denied self-identified agent
  with outstanding verification follows the agent-verification card to collect
  missing credentials, not a phone-support-only referral. Never provide a code,
  remote unlock, or direct entry while denial/verification is unresolved; preserve
  non-negotiable Trust and Safety and rental-scam restrictions.
- **Safehaven agent troubleshooting (November 9 XA update):** Only for an
  otherwise authorized agent and applicable mechanical lockbox, fully cycle the
  rollers three or four revolutions before entering the code; do not guarantee
  success. If the keypad fails while the agent is live on the call, the XA must
  verify agent identity/current Trust and all property/appointment/access gates
  before sharing an applicable mechanical code. This does not authorize codes
  in a ticket draft, remote unlock, denial bypass, or general buyer/former-owner/
  vendor access. Source:
  https://opendoor.slack.com/archives/C02K6JVSNUF/p1794252711113129.
- When the customer asks specific questions about showing length, lockbox signage,
  or whether additional access is required, address those questions in the
  customer reply together with any ask about whether the appointment occurred or
  help is still needed. State what the verified confirmation or record supports
  and what remains unverified; do not answer only with whether they completed the
  tour or still need help.
