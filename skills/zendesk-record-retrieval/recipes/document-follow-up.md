# Signed-document or counteroffer follow-up

Apply AGENTS.md, [same-ticket follow-up](same-ticket-follow-up.md) and the mandatory
[document-handoff guide](../guides/document-handoffs.md) when selecting an owner or
preparing a handoff note. The current playbook remains authoritative.

- Read the specific preceding request, latest supplied documents/status and any
  later substantive answer. Reuse sufficient verified ticket evidence; obtain
  current comments for a latest-reply check. A greeting, acknowledgment, solved
  status or assignment alone does not prove the document work is complete.
- A possible repeated/split concern uses the existing bounded related-ticket
  check: [Repeated concern and login](../ROUTING-DETAILS.md#repeated-concern-and-login).
  Inspect matched candidate comments together only after requester, exact
  property/transaction and support concern match. Continue in the substantive
  owner conversation and keep the other ticket's full verified URL.
- A verified later answer may support no reply on an older SMS without resolving
  outstanding signatures/document return on the email. Keep that distinction
  and next action explicit; [ticket consolidation](ticket-merge.md) handles an
  actual proposed merge, not ordinary assignment or a substitute closure.
- Discover only missing ownership/transaction facts needed for the handoff.
  Rank eligible responsible owners using the guide; do not automatically assign,
  forward files, send a message, post a note or claim document acceptance.

Return the appropriate reply/no-reply disposition and internal note. If completion
is unverified, do not claim the issue resolved or recommend closing for that reason.
Preserve attachments and existing unsent work; never repeat a completed handoff.
