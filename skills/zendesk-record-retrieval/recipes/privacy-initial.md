# Initial customer-profile deletion

Apply AGENTS.md. Read only SKILL.md → [Privacy and deletion requests](../SKILL.md#privacy-and-deletion-requests)
before drafting; reuse it if already loaded. Read the applicable linked Privacy
FAQ content and matching #privacy-escalations ticket thread/instructions as that
section requires. Use current direct Slack reads/search for the specific case;
no repeated cross-source search solely to prove the same absence. Missing or
conflicting guidance is unknown, not permission to improvise.

- Verify ticket/requester/channel/latest intent and relevant prior replies. Reuse
  sufficient server-held Zendesk evidence; check current comments when newer
  activity is requested or the supplied coverage is insufficient.
- Distinguish customer-profile deletion from removing one property, public pages,
  photos/search results, mobile-app deletion and a state privacy request. Property
  absence and duplicate initial tickets alone do not create an objection.
- **Mobile-app account deletion is a customer answer, not a hold.** When the ask is
  deleting the app account, read the mobile-app account deletion passage in
  SKILL.md → [Privacy and deletion requests](../SKILL.md#privacy-and-deletion-requests)
  and reply with the documented in-app path (Account tab → Personal Information →
  Request to delete account → confirm), plus the Help Center article's approved
  fallback when the app errors or the option is missing. Point a customer who also
  wants personal information deleted to `privacy.opendoor.com`. Do not withhold the
  customer reply for a failed in-app attempt; hold only for a genuinely unresolved
  request type or eligibility, and name that question.
- For an initial profile-deletion request, follow the existing portal response
  and exact current website in the Privacy section. Do not add objection macros,
  directory disclaimers, an automatic Slack draft or an escalation workflow.
- Portal failure/pushback/prior objection → [privacy follow-up](privacy-follow-up.md).
  Property-only removal → [property removal](property-removal.md). A cancellation
  plus preliminary-offer concern retains its separate verified-stage explanation;
  do not let privacy routing swallow it.
- No unrelated customer/property/offer research for the routing-only reply. Keep
  required case-specific Privacy checks; if they cannot be completed, explain the
  exact blocker internally rather than invent an eligibility state or process.

Return both complete boxes, normal email/SMS voice unless a directed verbatim macro
supersedes it. Do not claim deletion, suppression, cancellation, submission or send.
This card changes navigation, not the approved Privacy wording or action permissions.
