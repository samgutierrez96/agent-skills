# XA Notes — optional compatibility summary

The complete note workflow, templates, standing wording, shorthand index, and
OpsHub posting procedure remain authoritative in `skills/xa-notes/SKILL.md`.
The full skill is the warm-up entry. This compatibility summary is not a
separate preparation requirement and cannot replace the full source. If the full
skill is present, do not read this summary; the first caller reuses that source.

## Output contract

- Warm-up (`ready`, skill attachment, path-only message, or a new chat with no
  call shorthand): load the complete authoritative skill first, then reply exactly
  `Ready when you are.` Preparation uses file reads only, with no OpsHub actions.
- A routine note is only one fenced five-field note, in fixed order:
  `Property Address`, `Reason for Call`, `Customer Concerns`, `Solution
  Offered`, `Follow Up Link`.
- Put each label and its content on the same line, with one blank line between
  fields. Use `N/A` for missing address or follow-up-link values on ordinary
  notes.
- Do not add explanations, Slack drafts, tool notices, or routing commentary.

## Fast routing

- Treat each new named caller as a new call. A follow-up with no caller keeps
  the prior caller and updates the prior note.
- Match shorthand against the full skill's index and use its exact template or
  standing wording. Already-written prose stays prose; do not replace it with
  a generic template.
- Cover every distinct ask, but do not turn scheduling context into a second
  call type.
- Do not invent facts, escalations, contacts, URLs, or future actions.
- Property facts from authorized lookups use only the current applicable
  **Qualified flips** record, never **Unqualified flips**. A newer unqualified
  denial cannot override a qualified expired offer; missing qualification is
  unresolved, not denial/no offer. Ordinary drafts remain tool-free except for
  the full skill's bounded filed-report link lookup.

## Tool boundary

- An explicit request to file an HQI/Home Feedback report follows the full
  skill's optional-action entry and on-demand report procedure. It submits one
  complete five-field report, verifies its link and posts the normal caller note
  only when requested. This is not triggered by past-tense filed-work wording
  or `Post it` alone. Reuse confirmed reports when only note posting remains.

- Ordinary notes use zero tools, except the full skill's silent listing-type
  check and bounded read-only completed-work link lookup. When the XA reports
  completed work in their own words, reuse its verified URL or retrieve the
  matching Slack, ticket, report or document link under Part 11 and include it
  once. Anything filed/reported/posted/sent in a named Slack channel uses that
  channel's bounded current-message read before asking for a link; this is not
  limited to HQI or tech support. Preserve Part 11's case-match, access and lookup
  limits. An unresolved required link keeps the draft unposted with a concrete
  blocker; never invent a link or broaden the search. This authorizes no new
  report, escalation, file upload/share, Slack send or OpsHub post.
- A direct command to post the selected note, such as `Post it` or
  `post the corrected note please`, authorizes OpsHub lookup and posting for
  that retained caller and draft. Direct fix/correct/update/edit commands for
  this call's verified already-posted note authorize only Part 11's in-place
  update. Without its receipt, revise the draft only. Source saves, draft-only
  requests and quoted or reported commands do not authorize a write.
- On a post, use the caller's customer page, not merely the property owner;
  use one parallel lookup batch, reuse `whoami`, then create a new note.
  An explicitly posted correction instead updates the verified original
  same-call note using `UpdateCustomerNote` under Part 11; reuse its receipt,
  avoid repeated unchanged-context lookups, and never fall back to create/delete
  or automatically retry an unconfirmed update. Empty
  phone results must take the full skill's bounded shared-context recovery
  before requesting another identifier.
- Use callable OpsHub tools directly. Missing deferred tools follow the full
  skill’s exact-name, bind-once rule before lookup; never enumerate unrelated
  tools, retry uncertain mutations, browse, or search files for routine notes.

## Loading rule

A full source-text attachment of the authoritative skill satisfies loading; reuse it
without rereading CORE or SKILL.md. Otherwise load only the complete
`skills/xa-notes/SKILL.md` on warm-up, in bounded
chunks that retain the full contents without truncation. Do not reply Ready
after loading only CORE. Reuse the full skill for the first note and later
notes in the same chat. If a note arrives without preparation, load the full
skill before drafting. If exact content is unavailable or truncated, reload
the needed authoritative section before drafting.
